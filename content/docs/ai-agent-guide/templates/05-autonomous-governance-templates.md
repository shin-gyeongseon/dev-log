## 템플릿 13: 장시간 자율 작업 (Overnight Mode) 실행 프롬프트

* **사용 목적**: 사용자가 자리를 비운 사이(야간/백그라운드) 에이전트가 안전한 경계 내에서 자율 작업을 수행하고 예산을 초과하지 않게 통제.

```markdown
당신은 야간 무인 자율 개발 에이전트입니다.
지정된 목표를 자율적으로 완수하되, 다음 [운영 예산 및 안전 규칙]을 엄격히 준수하십시오.

### 운영 제약 및 예산 (Hard Limits)
1. **반복 횟수 제한**: 동일한 에러로 인한 재시도는 최대 3회까지만 허용 (초과 시 해당 작업 격리 후 다음 작업으로 전환).
2. **수정 파일 제한**: `src/legacy/` 하위 파일 및 테스트 파일만 수정 가능.
3. **절대 금지 행위 (Instant Termination)**:
   - 외부 프로덕션 배포 (`npm publish`, `deploy`, `git push origin main`)
   - 데이터베이스 Drop / Truncate 명령
   - 외부 결제 또는 메시지 전송 API 호출
   - `.env` 파일 수정 또는 외부 네트워크로의 파일 업로드

### 완료 시 모닝 리포트 작성
작업 종료 후 `reports/morning-report-{date}.md`에 결과를 기록하십시오.
```

## 템플릿 14: 익일 아침 확인용 모닝 리포트 (Morning Report) 템플릿

```markdown

## 2. 완료된 작업 및 변경 사항
| 작업명 | 수정된 파일 | 추가된 테스트 | 통과 여부 |
| :--- | :--- | :--- | :---: |
| 레거시 결제 모듈 단위 테스트 보강 | `src/payment.ts` | 5개 케이스 | ✅ PASS |
| 데드 코드 정리 (미사용 유틸 3종) | `src/utils/old.ts` | 기존 회귀 검증 | ✅ PASS |

## 3. 중단/보류된 작업 (인간 판단 필요)
- **작업명**: 회원 탈퇴 로직 리팩토링
- **중단 사유**: 외래키 제약조건 위반 에러 발생 (데이터 손실 위험으로 자율 중단)
- **인간 결정 필요 사항**: 탈퇴 회원의 주문 내역을 Soft Delete할 것인지 Hard Delete할 것인지 결정 필요

## 4. 실행 증거 및 메트릭

- 코드 커버리지 변화: 72.4% $\rightarrow$ 78.1% (+5.7%p)
```

## 템플릿 15: 위험도 분류표 및 인간 승인 게이트 (Human Gate Decision Matrix)

| 위험도 | 작업 유형 | 에이전트 자율 허용 범위 | 인간 승인 필수 여부 |
| :---: | :--- | :--- | :---: |
| **Tier 1 (저위험)** | 코드 읽기, 테스트 실행, 주석 보강, 단위 테스트 추가 | **완전 자율 (Full Auto)** | 불필요 |
| **Tier 2 (중위험)** | 비즈니스 로직 리팩토링, 신규 API 엔드포인트 구현, UI 컴포넌트 수정 | **자율 구현 + 증거 제출** | PR 검토 시 승인 |
| **Tier 3 (고위험)** | DB 스키마 마이그레이션, 인증/인가 로직 수정, 외부 의존성 업그레이드 | **계획/검증 스크립트 작성만 허용** | **실행 전 사전 승인 필수** |
| **Tier 4 (치명적)** | 프로덕션 배포, 데이터 삭제, 결제 연동, 시크릿 키 갱신 | **에이전트 단독 실행 금지** | **인간 직접 실행 / 다중 서명** |

## 템플릿 16: AI 에이전트 실패 사고 회고록 (Post-Mortem Template)

```markdown
# [에이전트 사고 회고] {사고명}

- **발생 일시**: {YYYY-MM-DD HH:mm}
- **영향 범위**: {예: 로컬 개발 DB 테이블 손상, 가짜 테스트로 인한 버그 머지 등}

### 1. 근본 원인 (Root Cause)
- [ ] 프롬프트 명세 모호성
- [ ] 테스트 오라클 부실 (가짜 성공 보고)
- [ ] 에이전트 권한 과다 부여
- [ ] 인간 검토자의 맹목적 승인

### 2. 재발 방지 대책 (Action Items)
1. **룰셋 업데이트**: `.agent-rules`에 `{금지 규칙}` 추가
2. **테스트 강화**: CI 파이프라인에 변이 테스트 또는 네거티브 검증 단계 추가
```
