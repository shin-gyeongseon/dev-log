## 템플릿 7: 테스트 오라클 검증 및 네거티브 테스트 프롬프트

* **사용 목적**: 에이전트가 단언문 없는 허위 테스트를 작성하거나, 실패하지 않는 가짜 테스트를 만드는 것을 방지.

```markdown
당신은 엄격한 테스트 QA 엔지니어입니다.
새로 작성된 기능에 대해 [유효성 검증 테스트]를 구현하십시오.

### 필수 검증 원칙
1. **의도적 실패 증명 (Negative Verification)**:
   - 정상 케이스뿐만 아니라, 비정상 입력값(빈 문자열, 음수, 허용되지 않은 권한)에 대해 반드시 테스트가 실패하거나 의도된 Error를 던지는지 확인하십시오.
2. **단언문(Assertion) 충실도**:
   - 단순히 `expect(response).toBeDefined()` 같은 무의미한 검사는 금지합니다.
   - 반환 데이터의 특정 필드 값, HTTP 상태 코드, DB 영속성 상태를 정확히 검증하십시오.
3. **증거 제출 형식**:
   - [테스트 실행 명령]: `npm test path/to/test`
   - [실행 결과 원본 로그]:
   - [검증된 엣지 케이스 목록]:
```

## 템플릿 8: 변이 테스트 (Mutation Testing) 프롬프트

* **사용 목적**: 에이전트가 만든 테스트 스위트가 실제 결함을 잡아낼 수 있는지 '코드 돌연변이'를 주입하여 검증.

```markdown
작성된 테스트 스위트의 신뢰도를 검증하기 위해 [수동 변이 테스트(Manual Mutation Test)]를 수행하십시오.

### 수행 절차
1. 구현 코드의 핵심 조건문(`if (a > b)` $\rightarrow$ `if (a >= b)` 또는 `status === 'ACTIVE'` $\rightarrow$ `status === 'INACTIVE'`)을 의도적으로 1군데 변소(Mutate)하십시오.
2. 테스트를 실행하십시오.
3. **판정 기준**:
   - ✅ **성공 (Killed)**: 테스트가 실패(Fail)하여 돌연변이를 잡아냄 $\rightarrow$ 테스트 신뢰성 입증.
   - ❌ **실패 (Survived)**: 코드를 망가뜨렸는데도 테스트가 여전히 통과함 $\rightarrow$ 테스트 단언문이 불완전함. 테스트 보강 필요.
4. 변이 테스트 결과를 보고서로 제출하고, 임의 변경했던 코드를 원상 복구하십시오.
```

## 템플릿 9: 브라우저 E2E 및 사용자 흐름 검증 프롬프트

* **사용 목적**: 백엔드/프론트엔드 연동 후 실제 브라우저 렌더링 및 클릭 플로우를 자율 검증.

```markdown
헤드리스 브라우저(Puppeteer/Playwright)를 사용하여 다음 사용자 시나리오를 검증하십시오.

### 시나리오
1. 로그인 페이지 접속 $\rightarrow$ 유효하지 않은 비밀번호 입력 $\rightarrow$ 에러 토스트 메시지 렌더링 확인.
2. 올바른 계정으로 로그인 $\rightarrow$ 대시보드 진입 확인.
3. 장바구니에 상품 추가 $\rightarrow$ 수량 변경 $\rightarrow$ 최종 결제 금액 DOM 계산값 일치 확인.

### 제출 증거
- 최종 완료 화면 스크린샷 파일 경로 (`artifacts/screenshots/final-checkout.png`)
- 브라우저 콘솔 에러 로그 (Error 0건 증명)
- 네트워크 탭 4xx/5xx 응답 없음 증명
```
