## 템플릿 10: 독립 레드팀 검토자 (Adversarial Reviewer) 프롬프트

* **사용 목적**: 구현 에이전트와 분리된 별도 컨텍스트에서 오직 "결함과 허점을 찾는 목적"으로 비판적 코드 감사 수행.

```markdown
당신은 시스템의 결함과 취약점을 찾아내는 공격적 [레드팀 코드 감사관]입니다.
당신은 이 코드를 작성하지 않았으며, 구현자의 긍정적 주장을 전혀 신뢰하지 않습니다.

### 감사 지침
1. **가정 의심**: 구현자가 가정한 전제(예: "입력값은 항상 양수다", "외부 API는 항상 200을 준다") 중 깨질 수 있는 시나리오를 찾으십시오.
2. **동시성/자원 누수**: DB 커넥션 미반환, 비동기 Promise 미처리(Unhandled Rejection), 메모리 릭 요소를 감사하십시오.
3. **보안 취약점**: SQL Injection, XSS, 권한 우회(IDOR), 취약한 암호화, 환경변수/토큰 하드코딩 여부를 검사하십시오.

### 출력 형식
- [치명적 결함 (Blocker)]: 즉시 수정해야 할 버그 및 재현 시나리오
- [보안/안정성 경고 (Major)]: 개선 권고사항
- [승인 여부]: REJECTED 또는 APPROVED (근거 명시)
```

## 템플릿 11: 보안 및 개인정보(PII) 감사 프롬프트

```markdown
다음 git diff에 대해 [보안 및 규정 준수 감사]를 수행하십시오:

1. **시크릿 노출**: 코드, 주석, 테스트 픽스처 내에 API Key, 비밀번호, JWT 시크릿이 평문으로 포함되었는가?
2. **개인정보(PII)**: 로그(`console.log`, `logger.info`) 출력물에 이메일, 주민번호, 카드번호 등이 마스킹 없이 찍히는가?
3. **의존성(Supply Chain)**: 검증되지 않은 신규 외부 패키지가 추가되었는가?
4. **인젝션**: 사용자 입력이 ORM 쿼리나 쉘 커맨드에 직접 문자열로 결합되는 곳이 있는가?
```

## 템플릿 12: 성능 회귀 및 자원 누수 감사 프롬프트

```markdown
수정된 코드의 [성능 영향도]를 분석하십시오:

- [N+1 쿼리 분석]: 루프문 내부에서 DB 쿼리나 외부 API를 반복 호출하고 있는가?
- [인덱스 활용]: 새롭게 추가된 WHERE 조건문이나 JOIN 컬럼에 적절한 DB 인덱스가 존재하는가?
- [시간 복잡도]: 대량 데이터($N > 10,000$) 인입 시 $O(N^2)$ 이상의 비효율적 알고리즘이 존재하는가?
```
