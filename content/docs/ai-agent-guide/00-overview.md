# AI 에이전트 기반 개발 실무 가이드
## 코딩 생성을 넘어, 검증 가능한 자율 개발 파트너로의 위임

---

## 1. 한 문장 핵심 메시지 (Core Message)

> **"AI 에이전트의 '말(Words)'을 믿지 말고, '증거(Evidence)'를 검증하라."**  
> AI 에이전트 기반 엔지니어링의 본질은 유려한 프롬프트를 작성하는 기교가 아니라, **명확한 제약 조건 분해, 구현자와 검토자의 분리(Red Teaming), 반증 가능한 테스트 증거 수집, 그리고 위험도별 인간 통제권(Human Gate)을 시스템화하는 것**이다.

---

## 2. 대상 독자 (Target Audience)

본 가이드는 다음과 같은 경험과 고민을 가진 소프트웨어 엔지니어 및 기술 리더를 대상으로 합니다.

- **현재 수준**:
  - Claude Code, Antigravity, Cursor, Windsurf, Copilot Workspace 등의 AI 에이전트 도구를 실무에 사용해 보았다.
  - 기능 개발 요청, 파일 편집, 명령 실행을 에이전트에게 지시할 수 있다.
  - 생성된 코드와 단위 테스트를 직접 읽고 실행해 보았다.
- **직면한 문제**:
  - 에이전트가 "테스트 통과 완료!"를 보고했음에도, 실제 배포하거나 브라우저에서 실행했을 때 버그가 터지는 경험을 반복하고 있다.
  - 에이전트가 작성한 테스트 코드의 오라클(검증 로직)이 올바른지 사람이 일일이 수동 확인하느라 시간과 피로가 가중된다.
  - 개인적인 프롬프트 요령(Tips & Tricks)에만 의존하고 있어, 팀 전체의 표준 개발 프로세스로 정착시키지 못하고 있다.
  - 무인 작업이나 장시간 자율 작업 시 파일 삭제, 잘못된 API 호출, 비용 폭증 등의 위험을 제어할 확신이 없다.

---

## 3. 독자가 도달할 최종 목표 (Target Goals)

1. **검증 가능한 파트너십 구축**: 에이전트를 단순한 자동 완성기가 아닌, 설계부터 테스트, 검토까지 검증 가능한 결과를 제출하는 동료 엔지니어로 활용할 수 있다.
2. **증거 기반 완료 판정**: "모든 테스트를 통과했습니다"라는 에이전트의 텍스트 주장에 속지 않고, **실패하는 테스트 증명(Failing First Demonstration)**, **변이 테스트(Mutation Testing)**, **독립 검토 보고서**를 통해 완료 여부를 수학적·논리적으로 판정할 수 있다.
3. **팀 표준화 및 거버넌스 확립**: 개인의 프롬프트 작성 능력에 좌우되지 않는 팀 공통 작업 명세서, CI/CD 감사 파이프라인, 위험도별 인간 승인 게이트를 구축할 수 있다.
4. **책임과 통제권 유지**: 에이전트에게 구현, 테스트, 검토를 대규모로 위임하면서도 시스템의 최종 안정성과 책임 소재를 사람이 완벽히 통제할 수 있다.
5. **사각지대 선제 방어**: 프롬프트 인젝션, 테스트 오라클 오염, 자기 확증 편향, 공급망 오염, 비결정적 플래키(Flaky) 테스트 등의 위험을 선제적으로 차단할 수 있다.

## 4. 기존 AI 코딩 콘텐츠와의 차별점

| 구분 | 기존 AI 코딩 가이드 / 프롬프트 팁 | 본 실무 가이드 (Agentic Engineering) |
| :--- | :--- | :--- |
| **핵심 초점** | "코드를 어떻게 빠르게 뽑아내는가" (생성 속도) | "생성된 코드를 어떻게 증거 기반으로 검증하는가" (신뢰성과 안정성) |
| **테스트 관점** | 에이전트가 만든 단위 테스트 실행 및 통과 확인 | 테스트 오라클 검증, 네거티브 테스트, 변이 테스트를 통한 가짜 통과 색출 |
| **에이전트 역할** | 1개 프롬프트 창에서 구현과 검토를 모두 수행 (단일 컨텍스트 편향) | 구현 에이전트와 독립 레드팀(검토) 에이전트의 관점 및 컨텍스트 격리 |
| **사람의 역할** | 생성된 코드를 사람이 눈으로 한 줄씩 전수 검토 | 고위험 영역 승인 게이트 통제 및 최소 증거 묶음(MEB) 감사 |
| **안전 & 운영** | 도구의 기본 안전장치에 의존 | 위험도 분류표, 예산(비용/시간/루프) 제어, 비상 정지 메커니즘 구축 |
| **팀 적용** | 개인 개발자의 단편적 노하우 공유 | 23종 표준 템플릿, CI/CD 연동, 사고 회고(Post-mortem) 자산화 |

## 5. 범위 및 제외 범위 (Scope & Out of Scope)

### 포함 범위 (In Scope)
- 모호성을 제거하는 4단 작업 명세(요구사항, 제약, 완료조건, 금지사항) 설계
- 코드 작성 전 저장소 탐색 및 증거 기반 사전 계획(Pre-mortem)
- 테스트 오라클 검증, 네거티브 테스트, 변이 테스트, 속성 기반 테스트
- 브라우저 E2E 사용자 흐름 자율 검증 및 시각적 회귀 증거 캡처
- 다중 에이전트 레드팀 감사 및 보안/성능 회귀 분석
- 위험도별 인간 승인 게이트(Human-in-the-Loop) 및 장시간 무인(Overnight) 작업 통제
- 10대 실무 도메인(CRUD, API, 인증, 버그수정, DB, 프론트, 동시성, 성능, 장애, 무인) 비교 사례
- 23종 복사 가능한 실전 템플릿 및 체크리스트 팩

### 제외 범위 (Out of Scope)
- LLM 모델 자체의 사전 학습(Pre-training)이나 파인튜닝(Fine-tuning) 수학적 이론
- 특정 상용 IDE 툴 하나의 단편적인 UI 메뉴 사용법 (본 가이드는 모든 에이전트 도구에 범용 적용 가능한 원칙과 인터페이스 중심)
- 일반적인 초급 프로그래밍 기초 문법 (Python, TypeScript 등의 기초 문법은 기지 상태로 전제)
